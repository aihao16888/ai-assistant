# AI Assistant 工作空间

> 我的个人 AI 助理工作空间，用于持续记录各项目进展，沉淀日常收集与整理的内容。

## 这个项目是什么

这不是一个代码项目，而是一个长期协作的工作空间。目录里的 Markdown 文档共同构成 AI 助理的上下文，让它能了解我每个项目的目标、进展和待办，并在后续任务中延续这些信息。

## AI 助理在这里做什么

1. **每日汇总**：按项目汇总当天的进展、决策和待办。
2. **按任务收集外部内容**：围绕我当前的任务，检索、筛选外部资料。
3. **整理成 Markdown**：对收集到的内容去重、提炼、结构化，写成文档。
4. **归档到合适目录**：按项目、主题、日期分层存放，而不是全部堆在根目录。

## 组织原则

- 目录先行：先确定归属，再写文档。
- 一个项目一个目录，一个主题一个位置。
- 根目录只保留总览类文件（README.md、AGENTS.md）。
- 未整理的资料先进入 inbox，整理后再归档。
- 同一内容只保留一份，优先更新已有文档而不是重复新建。

## 目录结构

```text
.
├── projects/              # 各项目目录：进展、决策、待办
│   └── <project-name>/
├── daily/                 # 每日汇总，按日期命名
│   └── YYYY-MM-DD.md
├── inbox/                 # 待整理的外部资料
├── topics/                # 跨项目的主题资料与调研
├── job-search/            # Java 后端求职、简历匹配与面试学习工作区
├── templates/             # 文档模板，统一格式
├── README.md              # 本文件：工作空间说明
└── AGENTS.md              # 与 AI 助理的协作约定
```

目录按内容需要逐步创建，不预先堆空目录。

## 使用方式

1. 我说明当天的任务或要跟踪的项目。
2. AI 助理按任务收集外部内容并整理。
3. 整理结果写入对应目录的 Markdown 文档。
4. 同步更新相关项目的进展文档。
5. 求职与面试准备统一维护在 [job-search/](job-search/)，不要混入通用 docs/ 或 topics/。

## 维护

- 定期清理 `inbox/`，把资料归档到 `projects/` 或 `topics/`。
- 定期回顾各项目进展，更新状态。
- 协作约定变更时，同步更新 [AGENTS.md](AGENTS.md)。
