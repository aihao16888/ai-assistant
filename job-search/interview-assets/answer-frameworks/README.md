# 面试回答框架

回答框架帮助组织表达，不是固定背诵稿。具体内容必须来自真实经历和准确的技术原理。

## 1. 项目介绍：背景—职责—关键工作—结果

1. 项目解决什么业务问题？
2. 系统主要业务流程是什么？
3. 本人负责哪个模块，边界在哪里？
4. 遇到什么具体问题？
5. 本人采取了什么行动，为什么？
6. 结果是什么，有什么证据？

## 2. 技术问题：结论—原理—项目映射—边界

1. 先用一句话回答核心结论；
2. 给出准确的专业术语和工作机制；
3. 结合真实项目说明为什么使用；
4. 说明适用条件、优缺点和替代方案；
5. 补充失败场景和保护措施；
6. 区分项目已经实现的内容与理论上可采用的改进。

## 3. 故障排查：现象—范围—证据—定位—处理—验证

1. 说明用户现象和影响范围；
2. 确定时间窗口、请求标识和关联服务；
3. 查日志、指标、SQL 或消息状态；
4. 缩小范围并提出可验证假设；
5. 说明根因和处理动作；
6. 说明如何验证恢复，以及是否有后续预防措施。

## 4. 行为类问题：STAR

- Situation：背景；
- Task：目标和本人责任；
- Action：本人采取的行动；
- Result：结果和证据。

不要把“我们团队做了什么”全部说成“我独立完成了什么”。
