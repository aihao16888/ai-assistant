## 3. 项目描述的候选表达

以下只是根据目前确认信息形成的表达草稿，最终必须按本人职责修改。

### 3.1 项目概述草稿

参与企业文档管理系统的后端开发与维护，系统涉及文档受控发布、OA 审批流转、文档安全编码生成及第三方系统数据同步。围绕重复提交、批量编号并发、审批消息处理和数据库查询等业务问题，参与相关后端功能开发与问题排查。

### 3.2 Redis 经历草稿

参与文档受控发布和安全编码生成相关功能：针对同一文件短时间重复提交的场景，使用 Redis 进行重复请求拦截；针对多个请求并发申请同一编号范围的场景，结合 Java 本地锁、Redis 分布式锁及序号缓存/递增机制控制编号生成过程，并将最新序号状态同步到数据库。

注意：具体锁算法、Redis 命令、失败恢复和唯一约束尚待核实，不应在未确认前写得更具体。

### 3.3 RabbitMQ 经历草稿

参与基于 RabbitMQ 的 OA 审批节点消息同步：OA 流程推进产生的相关消息同步至 DMS，DMS 根据当前审批节点和业务状态判断是否需要向第三方系统同步数据。

注意：消息生产者、交换机、队列、路由键、消费确认和失败重试机制仍需确认。

### 3.4 数据库问题排查草稿

曾排查编号查询中数据库数值字段与 Java 对象 String 类型不一致导致的查询行为异常，进一步关注参数绑定类型、SQL 执行计划及索引使用情况。

注意：在拿到 SQL 和 EXPLAIN 证据前，不直接写成“解决全表扫描”或“性能提升 X%”。
