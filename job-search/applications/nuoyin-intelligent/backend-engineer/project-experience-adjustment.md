# 诺因智能｜项目经历与简历调整记录

> 目标：根据诺因智能后端开发工程师岗位要求，决定 DMS 项目经历突出什么、保留什么，以及哪些事实需要先核实。  
> 状态：本轮简历取舍方案，待用户审计。  
> 简历正文：[DMS 简历项目经历模块](../../../profile/resume-projects/document-management-system.md)

## 1. 本轮结论

DMS 项目在诺因智能岗位简历中建议保留 5 条：

1. 项目业务范围与本人参与情况；
2. Redis 防止同一文件重复受控发布；
3. Java 本地锁与 Redis 分布式锁控制安全编码并发生成；
4. RabbitMQ 同步 OA 审批节点消息并按业务条件触发第三方同步；
5. Java 参数类型与数据库数值字段不一致的查询排查。

这 5 条分别对应 Java 后端业务开发、Redis、并发与分布式、消息队列、数据库问题排查。它们比单纯罗列技术栈更能体现真实项目场景。

## 4. 量化成果处理

当前没有可靠的性能前后对比、QPS、耗时、故障率或业务规模数据，因此不写“性能提升 X%”“支持高并发”“效率提升 X 倍”等表述。

目前可确认的具体业务量是单次批量生成约 50 个安全编码。这是批次规模，不是性能成果；仅在需要强调批量并发场景时使用。

后续如果能取得真实记录，可考虑补充重复请求拦截量、编号申请频率、SQL 执行计划与耗时对比、消息处理量等指标。
