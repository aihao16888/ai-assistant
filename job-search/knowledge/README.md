# Java 后端工程师核心知识库

> 目标：建立能用于开发、系统排查和技术决策的知识体系，而不是收集八股文或堆砌术语。  
> 本轮重构：2026-11-24。  
> 原则：先说明问题，再解释原因和机制，最后落到解决、排查与验证。

## 1. 这套知识库要解决什么问题？

后端工程师日常工作反复面对五类问题：

1. **程序为什么出现错误结果？** 例如并发覆盖、状态错乱、重复提交。
2. **接口为什么变慢？** 例如 SQL 慢、锁等待、线程池排队、连接池耗尽。
3. **服务之间为什么没有按预期协作？** 例如消息丢失、重复消费、超时和重试。
4. **多实例部署后为什么出现单机环境没有的问题？** 例如本地锁失效、Session 不共享、重复执行。
5. **如何证明问题已经解决？** 通过日志、指标、执行计划、数据库状态、测试和故障复现验证，而不是凭感觉判断。

每个专题都必须回答同一条链路：

~~~text
业务现象
  ↓
问题为什么发生
  ↓
底层机制是什么
  ↓
技术如何解决
  ↓
还有哪些边界和失败场景
  ↓
线上如何定位与验证
  ↓
项目中实际使用了什么
~~~

## 3. 后端工程师必须掌握什么？

这里的“必须掌握”不是要求背诵所有底层源码，而是要求能独立完成对应工作。

### P0：日常开发和线上排查必须能用

- Java：集合与对象基础、异常处理、并发、线程池、JVM 基础、Spring Boot 请求与事务机制。
- 数据库：数据类型、主键/唯一约束、索引、SQL 执行计划、事务、隔离级别、MVCC、行锁、死锁。
- Redis：常用数据结构、过期策略、原子命令、防重、幂等、分布式锁、缓存与持久化边界。
- 消息队列：生产者、交换机、队列、路由、消费者、ACK、Publisher Confirm、重复投递、重试和死信。
- 服务运行：HTTP 请求链路、超时、重试、连接池、线程池、日志定位、CPU/内存/磁盘/网络基本排查。
- 工程质量：Git 日常协作、单元测试、集成测试、日志和异常信息。

当前五份专题先覆盖 Java 并发、数据库、Redis、RabbitMQ 和分布式部署。Spring Boot、JVM、HTTP、Linux、测试工程仍需单独补齐；本轮不把尚未整理的内容标成已完成。

### P1：需要理解，遇到复杂场景能参与分析

- JVM GC 细节、类加载和内存诊断；
- 数据库复制、备份恢复、分区和读写分离；
- Redis 持久化、复制、哨兵/集群和缓存一致性；
- MQ 消息顺序、限流、Outbox、延迟重试和死信治理；
- 微服务注册发现、网关、熔断、分布式追踪和最终一致性。

### P2：了解即可，不冒充项目经验

- Kafka、RocketMQ、MongoDB、Kubernetes 等当前没有确认生产实践的技术；
- 特定中间件的高级参数和底层源码细节；
- 与当前岗位和项目无关的冷门实现细节。

## 4. 怎么判断自己是否真正掌握？

不以“看完文档”作为完成标准。每个 P0 专题至少做到：

1. 不看资料，能画出一次典型问题的发生过程。
2. 能解释核心概念，不能只说出缩写。
3. 能给出至少一种解决方案，并说明适用条件。
4. 能说出方案失效或带来新问题的场景。
5. 能说出排查时查看的日志、命令、SQL 或指标。
6. 能把原理与项目事实区分开：已实现、参与过、待核实、仅为通用方案。

## 5. 学习顺序

建议按一条后端请求链路学习，而不是按名词随机跳转：

1. Java 请求执行、线程与线程池；
2. 数据库读写、索引、事务和并发控制；
3. Redis 缓存、防重、锁和计数器；
4. RabbitMQ 消息异步处理与可靠性；
5. 多实例部署、服务调用和跨服务一致性；
6. Spring Boot、JVM、HTTP、Linux 和测试专题补齐。

## 6. 项目映射边界

DMS 当前可用于学习的真实场景包括：

- Redis：受控发布防重、安全编码序号缓存/递增和分布式锁；
- RabbitMQ：OA 审批节点消息同步到 DMS；
- 数据库：数值字段与 Java String 参数类型不一致的查询问题；
- Java 并发：安全编码批量生成时的本地锁；
- 多实例：系统涉及三台服务器，但每台服务器的部署角色尚未核实。

项目中具体的 Key、SQL、索引、锁配置、消息 ACK、重试机制和部署拓扑，仍需代码或用户确认。通用技术方案不能写成项目已经实现的事实。
