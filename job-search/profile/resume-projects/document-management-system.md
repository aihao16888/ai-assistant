## 1. 简历可用版本

**项目名称：** 企业文档管理系统（DMS）  
**项目角色：** Java 后端开发（具体负责模块、项目时间待确认）  
**技术栈：** Java、Spring Boot、Redis、RabbitMQ、SQL

- 参与企业文档管理平台后端开发与维护，涉及文档受控发布、OA 审批流转、安全编码生成及第三方系统集成。
- 针对同一文件短时间重复发起受控发布的问题，使用 Redis 记录文件标识并拦截重复请求，避免重复触发后续流程。
- 针对多个部门并发申请同一编号范围产生的序号竞争，结合 Java 本地锁与 Redis 分布式锁控制生成过程，利用 Redis 缓存并递增最新序号，再同步至数据库序号表，支撑单次约 50 个安全编码批量生成。
- 参与基于 RabbitMQ 的 OA 审批消息同步，DMS 根据审批节点及业务状态识别处理时机，并按业务条件向第三方系统同步数据。
- 排查编号查询中数据库数值字段与 Java String 参数类型不一致的问题，将查询参数调整为 Long，使查询恢复预期的等值匹配行为。

以上 5 条是目前根据用户已描述的项目事实形成的简历初稿。正式投递前，仍需确认个人参与边界、项目时间、数据库产品和部分实现细节。

## 4. 事实边界与投递前核验

### 已有用户描述支持的事实

- DMS 涉及文档受控发布、OA 审批、自动生成安全编码和第三方系统同步。
- 同一文件短时间重复提交时，使用 Redis 进行重复请求拦截。
- 安全编码由组织代号、车型代号、年月和递增序号等部分拼接，要求全局唯一。
- 编号生成使用 Java 本地锁和 Redis 分布式锁；Redis 参与序号缓存、递增，最新序号状态同步至数据库序号表。
- 单次请求可能批量生成约 50 个安全编码。
- RabbitMQ 用于 OA 审批节点相关消息同步到 DMS；DMS 识别目标节点后按业务条件向第三方同步数据。
- 编号查询存在数据库数值字段与 Java String 参数类型不一致的情况，参数调整为 Long 后查询恢复预期的等值匹配行为。

## 5. 量化成果：目前不编造

当前可以安全使用的业务量化信息是“单次批量生成约 50 个安全编码”。这描述的是业务批次，不是性能提升指标。

如果后续能从系统或脱敏记录中取得真实数据，可以考虑补充：

- 受控发布日均提交量、重复请求拦截量；
- 编号申请频率、单次批量数量、并发申请场景；
- 查询优化前后的执行计划、扫描行数和耗时；
- 消息处理量、消费失败率或重试情况。

没有数据就保留定性表述，不写“效率提升 30%”“支持高并发”等无法证明的结果。
