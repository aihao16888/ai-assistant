# 简历项目经历素材库

> 本目录只存放可以直接提炼进简历的项目经历版本，不替代完整项目事实，也不替代面试故事。

## 1. 与其他目录的边界

| 资料 | 回答的问题 | 内容形态 |
|---|---|---|
| profile/projects | 我实际参与了什么？ | 完整业务背景、职责、流程、技术事实、待核实项 |
| profile/resume-projects | 简历上应该写什么？ | 4–5 条高度凝练、可复制的项目经历 |
| interview-assets/story-bank | 面试官追问时怎么讲？ | 背景、问题、个人行动、技术机制、结果、追问 |

简历项目经历必须从项目事实中提炼；故事库负责展开简历中的关键句子。三者不能互相替代。

## 2. 当前项目

- [企业文档管理系统（DMS）简历项目经历](./document-management-system.md)：包含可复制的 5 条简历表述、岗位定制取舍、故事映射和待核实事项。

## 3. 维护规则

1. 默认每个项目控制在 4–5 条，每条只表达一个主要贡献。
2. 每条尽量包含“业务问题/场景 + 本人行动 + 技术手段 + 结果或目标”。
3. 没有真实数据时使用准确的定性结果，不编造 QPS、耗时、提升比例或业务规模。
4. 每条简历表述必须有项目事实来源，并关联一个故事 ID。
5. “参与开发”“负责模块”“协助排查”必须按真实参与边界选择，不能为了简历效果升级措辞。
6. 公司专项简历可以调整顺序和强调重点，但不能改变项目事实。
7. 项目技术栈只列本人真实使用且能解释的技术；没有生产实践的技术不得包装成项目经验。

## 4. 更新流程

项目事实更新 → 简历项目经历提炼 → 岗位匹配与取舍 → 故事映射 → 用户审计 → 形成投递版本。
