> **爆款不是“创作”出来的，是用户行为数据标注出来的“需求地图”。**

> 先当考古学家，拆别人；再当工程师，用模板组装。

## 三、怎么拆别人的帖子

### 1. 先找“异常值”，不是找“最高赞”

《小红书 AI 提效工作流》讲得很清楚：

> 看同一个博主的历史数据。平时 2 赞，某篇 5 赞，这篇就是异常候选。

因为最高赞可能是大号自带流量；  
异常值才是“这篇内容本身做对了什么”。

### 2. 一张拆解表

| 维度 | 记录什么 |
|---|---|
| 来源 | 链接、作者、粉丝量、发布时间 |
| 数据 | 点赞、收藏、评论；收藏/点赞比 |
| 人群 | 这篇给谁看 |
| 痛点 | 开头戳了什么 |
| 选题 | 一句话说清“讲什么” |
| 封面 | 大字/对比/截图/人物/表格/纯文字 |
| 标题 | 钩子、爆点、催促；用了哪些关键词 |
| 开头 | 前 3 秒/前 3 行怎么抓人 |
| 结构 | 痛点→方案→结果？清单？对比？故事？ |
| 证据 | 截图、数据、before/after、真实经历 |
| CTA | 评论、私信、收藏、关注 |
| 评论区 | 用户反复问什么、质疑什么 |
| 可复用 | 你能学哪一个动作 |
| 不能复用 | 别人的数据、经历、案例、身份 |

### 3. 拆解顺序

```text
先看数据 → 再看选题 → 再看封面/标题 → 再看开头 → 再看结构 → 最后看评论区
```

不要一上来抄文案。  
先判断“这篇为什么被点、被收藏、被评论”。

### 4. 拆账号，不只拆单篇

《AI 自媒体 - 小红书》建议看 10～20 个同领域账号，记录：

- 人设：实用型/治愈型/励志型；
- 封面：色调、排版、字体；
- 选题：常发哪几类，哪类更容易爆；
- 文案：情感路线还是干货路线；
- 标题：常用关键词、句式；
- 标签：常用哪些标签。

## 四、怎么组装成自己的帖子

### 7 层工作流

```text
固定对标池
  ↓
采集（标题/文案/封面/互动/时间）
  ↓
异常值识别（同博主波动，不是只看最高赞）
  ↓
分析（词云、关键词、结构、意图）
  ↓
二创（换人群/场景/工具/结果）
  ↓
发布（标题/封面/正文/标签）
  ↓
复盘（数据回写，下一轮）
```

### 组装的 4 个替换

《小红书 AI 自媒体（视频）》的脚本方法：

> 保留参考文案的开头句式、介绍顺序和表达节奏；  
> 替换工具、使用场景和效果；  
> 不要沿用原作者的个人经历、使用数据和亲测结论。

四个可替换：

1. **换人群**：大厂职场 → 程序员/求职者；
2. **换场景**：简历 → JD 判断/岗位核实；
3. **换工具**：通用 AI → Agent/Codex/Claude；
4. **换结果**：涨粉 → 省时间/避坑/拿到面试。

### 组装公式

> **别人的结构 + 你的真实数据 + 你的身份/经历 + 你的观点 = 你的帖子**

不是：

> 别人的文案 + 改几个词 = 你的帖子

## 五、写作公式

### 1. 选题公式

> 人群 + 场景 + 问题 + 结果

例子：

- 程序员 + 找工作 + 岗位太多/过期 + 先筛一遍
- 求职者 + 看 JD + 不知道是不是坑 + 3 个信号
- 内容创作者 + 做选题 + 没灵感 + 对标矩阵

### 2. 标题三件套

《小红书商单号》拆的标题结构：

| 部分 | 作用 | 例子 |
|---|---|---|
| 钩子 | 定位人群/建立关联 | 程序员、求职、AI 岗 |
| 爆点 | 具体效果/对比/情绪 | 20 个 JD、3 个坑、别再刷了 |
| 催促 | 行动暗示 | 建议收藏、看完再用、评论区留 JD |

常见 5 种标题法：

1. 权威加持；
2. 万能解法；
3. 对比碾压；
4. 数据证明；
5. 情绪浓度。

### 3. 封面

《AI 自媒体 - 小红书》列了 24 类封面。新手先掌握 5 类就够：

- 放大型：一个大结果/大字；
- 对比型：before/after；
- 数字型：N 个方法/N 个坑；
- 纯文字型：一句反常识；
- 截图/聊天型：真实记录。

### 4. 图文结构

> 引起共鸣 → 激发好奇 → 提供方法 → 展示效果 → 鼓励互动

### 5. 视频结构

> 0～3 秒结果/问题 → 3～10 秒痛点 → 10～40 秒方法 → 40～50 秒翻车/边界 → 50～60 秒提问

## 六、二创边界

《小红书商单号》和《AI 提效工作流》都强调了边界：

- 不直接搬运；
- 不复制别人的图片/数据/经历；
- 二创是“换人群、换场景、换工具、换结果”，不是洗稿；
- 形式改造 > 30%，内容原创 > 80%；
- 用 AI 仿写，但必须加自己的真实经历和截图；
- 参考文案的“结构”可以学，“作者的经历和数据”不能拿。

一句话：

> **学结构，不学内容；学逻辑，不学数据。**

## 七、5 种持续选题法

来自《小红书虚拟产品（AI 赋能）》“如何搭建笔记选题系统”：

| 方法 | 一句话 |
|---|---|
| 提案式 | 从“用户为什么还没买”出发，回答 4 个购买阻力 |
| 卖点聚焦 | 一个卖点打透一篇，不在一篇里讲完所有 |
| BERT 搜索 | 从核心词扩展语义相关的问题 |
| 里程碑 | 记录“第一次/第 N 天/从 0 到 1” |
| 观点 | 有争议但有道理的一句话，适合传播 |

对个人 IP，优先用：

- BERT 搜索：覆盖真实搜索；
- 里程碑：记录实验；
- 观点：建立辨识度；
- 提案式/卖点聚焦：有产品后再用。

## 八、应用到“AI 帮找工作”

### 拆 5 条对标

| 对标 | 拆什么 | 我们学什么 |
|---|---|---|
| C3 招聘邪修 | 身份 + 3 步 + 一个狠洞察 | “很多岗位挂着但不招” |
| D1 这个 JD 能投吗 | 疑问句 + 手写拆 JD + 评论征集 | 形式 |
| X1 Codex 自动投简历 | 一句话结果 + 录屏 | 流量，但不做主推荐 |
| X2 4 步改简历 | 4 步 + 提示词卡片 | 高收藏结构 |
| X3 Claude 全流程 | dashboard + 标准 + 人工投 | 信任/精投 |

### 我们的组装

> **C3 的洞察 + D1 的形式 + 我们的真实 JD 数据 + 程序员的身份**

不是：

> 抄 C3 的“17 年 HR”身份，或抄 X1 的“自动投递”。

### 第一条结构

1. 一个真实 JD（脱敏）；
2. 先给判断：能投/谨慎/别投；
3. 3 个信号：职责模糊、年限/薪资不匹配、隐性加班/外包；
4. 一句简历建议；
5. 边界：不自动投，人工确认；
6. CTA：评论区留 JD。

## 九、常见错误

1. **只看最高赞，不看异常值**：大号最高赞可能不是内容本身好。
2. **只拆文案，不拆封面/标题/开头**：用户先看到的是封面和标题。
3. **只拆单篇，不拆账号**：单篇是运气，账号是结构。
4. **直接洗稿**：换几个词，不叫二创。
5. **拿别人的数据当自己的**：这是最危险的。
6. **AI 一上来写全文**：应该 AI 拆结构、你填真实内容。
7. **一条内容讲完整个系统**：一条只讲一个核心点。
