## 选题判断

**AI 做 PPT 值得作为第一个专题。** PPT 是向特定听众展示信息的形式。给上级看，要能说明进展、成效和待决定的事项。给客户看，要能讲清问题、方案、可信依据和下一步。给用户看，要能说明用途、演示操作和使用结果。业绩汇报是其中一个具体场景。

系列分两步。**先用 AI 做出一套可以打开和播放的初稿，再把素材、文字、叙事和图文设计做扎实。** Office PPTX 和 HTML 是两种交付方式，按听众如何观看、如何使用以及谁来接着改选择。专题的价值在于让读者看见原始材料如何一步步变成能讲、能看、能交付的演示。

## 四个子系列与十二个模块

| 子系列 | 模块 | 读者拿走什么 |
| --- | --- | --- |
| **一 · 先用 AI 做出一套 PPT** | **1. 写清生成任务。** 交代给谁看、希望对方看懂什么或做什么、有什么材料、讲多久、最后交什么。给一个视觉参考，说明期望的图表和文字密度。 | 一份可复用的生成任务单。 |
| | **2. 生成 Office 初稿。** 从材料生成 `.pptx`，打开、翻页，再实改一个标题或图表数据。 | 一套可在目标 Office 环境打开的初稿。 |
| | **3. 生成 HTML 初稿。** 用同一份材料生成浏览器幻灯片，验证如何打开、翻页、改字和分享。 | 一套可播放的网页幻灯片，并知道从哪里改稿。 |
| **二 · 把零散材料写成有价值的内容** | **1. 提炼结构。** 把行动记录、用户反馈、数据、截图提炼成「问题、行动、结果、依据、意义」。缺证据的地方标待补。 | 一张有出处的演示素材表。 |
| | **2. 润色成听众听得懂的话。** 结论写进标题，动词说清动作，长段压成要点，保留事实、职责归属和统计口径。 | 同一条原始记录到结构化要点、再到页标题的对照。 |
| | **3. 按用途补内容。** 向上汇报补证据和待决事项，客户展示补使用场景和可信案例，用户演示补操作例子与预期结果。 | 三种场景分别需要的内容清单。 |
| **三 · 把一页页串成一场演示** | **1. 先定整套顺序。** 例如项目汇报从结论到证据再到待决，客户演示从问题到方案、演示和试用。 | 从听众进入主题到理解下一步的提纲。 |
| | **2. 给每页安排一个任务。** 用一句话说出每页要回答的问题，再检查下一页接的是证据、原因、例子还是行动。 | 一份带页级问题与衔接句的分镜。 |
| | **3. 连着讲一遍。** 逐页试讲，合并重复内容，补上听众会追问的过渡和解释。 | 一套在规定时长内讲得顺的幻灯片与讲稿。 |
| **四 · 把图文设计做精美并完成交付** | **1. 给信息选对图。** 趋势配折线，前后对比用并排图，步骤用流程，产品体验用截图或演示。图注说清读者该看哪里。 | 一张图和文字互相解释的页面。 |
| | **2. 让整套设计统一而有层次。** 统一字体、色彩、留白、对齐和图表风格，按封面、图表、流程、案例等页面任务选版式。 | 一套版式规范，以及同一页修改前后的对照。 |
| | **3. 验收实际交付。** Office 试改文字、表格和图表，HTML 试投屏、交互、离线和链接，正式分享时按场景准备 PDF 或源文件。 | 一张成品检查表和给听众使用的文件。 |

**内容饱满**可以具体检查。每页有一句可复述的结论，配足以支撑结论的数据、截图、案例或解释。页面精美来自文字层级清楚、配图合适、重点醒目。整套连贯可以用一个问题验收，上一页让读者想问什么，下一页有没有接住。

例如同一份阶段工作记录写着「做了三次用户访谈，整理十条反馈，调整了两个操作步骤」。给负责人看，页标题可以提炼为「根据十条用户反馈，调整了上手流程中的两个步骤」，配反馈分类与前后流程，效果数据待补。给用户看，改成「新手如何完成这两个操作」，用前后截图和标注带着走一遍。这个例子中的数字只用于演示润色与换受众。

模块是内容储备。首篇先让读者看见一套 PPT 怎样生成和播放。后续分别写素材润色、整套故事线、图文升级和双格式交付，每篇集中验证其中一个具体问题。

## 首篇怎么写

**拟题「给 AI 一份项目材料，它能做出一整套讲得清的 PPT 吗？」** 用一份公开或明确标为模拟的项目阶段材料，包含原始记录、截图或少量可核对数据。先定一个观众，例如需要快速了解项目进展的同事。第一版用 Office 展示生成和实际改稿，后续用同一份材料做 HTML 对照。

1. 先放原始素材、一句话的展示目标，以及整套初稿缩略图。
2. 用五页快速过一遍「现在进展如何 → 为什么要做 → 实际做了什么 → 有哪些结果和证据 → 下一步做什么」的顺序。
3. 展示一页从 AI 初稿到修订稿的变化，选一个具体改动，例如把长段进展改成结论标题与前后截图。
4. 显示打开和翻页，现场改一处内容，将任务单和改稿检查项留给读者。

首篇验收看三件事。初稿能否打开、播放和修改，页与页能否顺着讲下来，改得最明显的一页能否让观众更快理解原素材。效率判断用实际生成和修改记录。Office 文件和 HTML 成品待制作和实测。

## 官方技术资料与交付判断

### Office PowerPoint 路线

- 微软的示例流程支持通过 PowerPoint 中的 Copilot 把 Word 文档生成演示初稿，再在 PowerPoint 中增删和修改内容。实际可选输入和 Copilot 可用性取决于许可、应用版本与组织设置。PowerPoint 的 `.pptx` 可用桌面版打开，网页版也支持编辑，具体功能随客户端而异。 [微软 Copilot 制作演示](https://support.microsoft.com/en-us/microsoft-365-copilot/prepare-your-presentation-with-microsoft-365-copilot) · [Copilot 常见问题](https://support.microsoft.com/en-us/powerpoint/frequently-asked-questions-about-copilot-in-powerpoint) · [PowerPoint 支持的格式](https://support.microsoft.com/en-us/powerpoint/file-formats-that-are-supported-in-powerpoint)
- 可编辑的原生图表可以在 PowerPoint 图表的工作表里更新数值，也可以链接 Excel 源文件。如果同事要接手，实测要分别改标题、表格单元格和图表源数据。组织用 OneDrive 或 SharePoint 协作时，还可以测试共同编辑、评论处理和版本历史。 [PowerPoint 图表](https://support.microsoft.com/en-us/powerpoint/training/use-charts-and-graphs-in-your-presentation) · [PowerPoint 协作](https://support.microsoft.com/en-us/powerpoint/work-together-on-powerpoint-presentations)

### 浏览器 HTML 幻灯片路线

- reveal.js 的基础包可以通过浏览器打开本地 `index.html`。外部 Markdown 等功能需要本地 Web 服务，本地使用演讲者视图也有这个要求。验收时在实际汇报电脑测试开场、翻页、字体与图片，以及需要用到的演讲者备注和断网表现。 [reveal.js 安装](https://revealjs.com/installation/) · [演讲者视图](https://revealjs.com/speaker-view/)
- HTML 可以嵌入网页内容，也可以用 Chart.js 等库实现悬停、点击和触屏提示。适合用一个演示页验证交互是否真的帮助解释数据，例如在同一张趋势图上切换地区。reveal.js 官方文档给出的 PDF 导出验证环境是 Chrome 和 Chromium，导出后要检查分页、背景和文字清晰度。 [reveal.js 媒体嵌入](https://revealjs.com/media/) · [Chart.js 图表交互](https://www.chartjs.org/docs/latest/configuration/interactions.html) · [reveal.js PDF 导出](https://revealjs.com/pdf-export/)

### 格式转换与交接

- 把 `.pptx` 是否能打开与页内元素是否能改当作两个验收项。程序可以生成原生文本形状和图表对象。PptxGenJS 的 HTML 转 PowerPoint 接口文档覆盖 HTML 表格，支持部分单元格样式，所以自定义 HTML 版式需逐项验证转换效果。整页图片进入幻灯片后按图片处理，页内文字和图表数据的修改回到源稿再导出。 [PptxGenJS 文本](https://gitbrent.github.io/PptxGenJS/docs/api-text.html) · [图表](https://gitbrent.github.io/PptxGenJS/docs/api-charts.html) · [HTML 表格转幻灯片](https://gitbrent.github.io/PptxGenJS/docs/html-to-powerpoint.html) · [PowerPoint 图片导出](https://support.microsoft.com/en-us/powerpoint/file-formats-that-are-supported-in-powerpoint)
- PDF 适合分发和查看固定版式。需要继续改稿的收件人应拿到相应的 `.pptx` 或 HTML 源文件，浏览器演示的字体、素材和脚本依赖也要随交接检查。 [Microsoft PDF 导出](https://support.microsoft.com/en-us/powerpoint/training/save-powerpoint-presentations-as-pdf-files) · [reveal.js 安装](https://revealjs.com/installation/)

### 同素材实测建议

用同一份自编或公开材料、源数据、目标受众与时长，分别生成 PowerPoint 和 HTML 初稿。固定两版的页级结论，例如用在项目汇报时都要讲摘要、进展趋势、原因、行动与待决事项。记录生成耗时和改到可交付的总耗时，逐项回查数字、单位和时间范围。给两版相同的临时变更，实改一个标题和一个数字，再让图表同步。最后检查目标设备演示、队友能否接手改稿、交互是否正常、PDF 是否可读，并记录分别交给演示人和观众的文件。
