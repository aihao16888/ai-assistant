## 一、什么时候建立单篇制作目录

只有当一个候选选题已经明确读者问题、内容价值和可行的证据路径，准备实际制作时，才在这里建立单篇目录。

不为每条原始帖子或每个初步想法建立文件夹。一个大主题也不等于一个系列；先确认某个具体角度有独立价值，再决定是否需要多篇内容。

AI 求职的 A-001-jd-pitfall/ 是已有案例草稿，保留作为一个具体应用方向，不代表账号主线或默认首发。

## 二、单篇制作包可以包含什么

根据内容类型选择文件，不要求每篇都创建全部文件：

~~~text
04-series/
├── README.md
└── <内容ID>-<短名称>/
    ├── brief.md          # 这篇内容回答什么、给谁看、读者收获
    ├── research.md       # 专题研究、来源、事实和证据映射
    ├── case-log.md       # 实际操作/实验记录；不需要实测时可省略
    ├── script.md         # 正文、图文页内容或视频分镜
    └── assets/           # 截图、录屏、示意图等素材
~~~

文件可以合并或省略。例如，简单的技术概念解释可能只需要 brief.md、research.md 和 script.md；真实应用实测则通常需要独立的 case-log.md。

## 三、每份文件应该回答什么

### brief.md：编辑判断

- 目标读者和具体场景；
- 本篇核心问题；
- 为什么值得讲；
- 读者看完能获得什么；
- 当前结论；
- 最关键的证据；
- 必须说明的限制；
- 计划采用的表达方式（暂定）。

### research.md：研究证据

- 需求信号及来源 ID；
- 相关帖子和评论中的问题；
- 官方文档、版本、日期和技术事实；
- 现有内容已经讲了什么、缺少什么；
- 重要结论与对应证据；
- 仍不确定的事项；
- 隐私、版权、成本和平台风险。

### case-log.md：真实操作

- 任务、输入、环境和日期；
- 模型/工具/版本/关键配置；
- 测试前确定的评价标准；
- 实际步骤、输出和证据；
- 错误、遗漏、人工介入和修正；
- 耗时、成本和限制；
- 结论适用范围。

### script.md：面向用户的表达

- 本篇最终角度和核心结论；
- 选用的叙事方式；
- 标题候选和封面表达；
- 正文、图文页或视频分镜；
- 截图/录屏/图示安排；
- 需要保留的来源说明；
- 互动问题（如有必要）。

这些是内部制作资料的组织方式，不是公开笔记的统一写作模板。

## 四、制作完成前的判断

- 内容是否回答一个清楚的问题？
- 读者收获是否具体？
- 关键结论是否有证据？
- 亲测、官方资料、他人经验和推断是否区分？
- 是否诚实展示失败、人工介入和限制？
- 视觉材料是否帮助读者理解或验证？
- 是否保护个人信息、工作资料和账号凭证？
- 是否检查版权和小红书当前 AI 内容声明要求？

通过审核后再发布，并在 05-published/ 建立真实发布记录。
