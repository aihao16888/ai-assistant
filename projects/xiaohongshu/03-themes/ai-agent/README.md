## 二、目标受众

不是“所有程序员”，而是：

> **想用 AI Agent 提效，但不知道怎么开始、怎么判断有没有用的人。**

包括：

- 内容创作者：选题、资料整理、脚本、封面；
- 职场人：JD 分析、简历、面试、日报；
- 小老板/独立开发者：重复流程、客服、数据整理；
- 程序员：想看真实搭建，不想看概念。

## 三、内容主线

### 主线 1：Agent 实测

一期一个具体任务：

> 任务 → 以前怎么做 → Agent 怎么做 → 结果 → 成本/翻车 → 提问

任务池见 `02-benchmark/benchmark-matrix.csv` 的 4 组关键词。

### 主线 2：Agent + 求职

拆解后分成 A/B/C 三个系列：JD 避坑、找工作实验、简历/面试。详见 [series.md](series.md)。

这是目前更有数据支撑的方向：

- JD 避坑；
- AI 帮找工作；
- 岗位是否真在招；
- 简历匹配；
- 不自动投递，只做分析和判断。

### 主线 3：Agent 搭建日记

记录从 0 搭一个 Agent 的过程：

- 第 1 天：想解决什么；
- 第 3 天：做出什么；
- 第 7 天：哪里翻车；
- 第 14 天：有没有真的用起来。

适合 build in public，但不要第一条就做。

## 五、第一条内容方向

不建议：

- “我用 Agent 分析了 100 个 JD”；
- “Agent 自动投简历”；
- “0 代码搭建 Agent”教程。

建议：

> **“这个 JD 能投吗？我让 Agent 拆了它的 3 个隐藏信号。”**

结构：

1. 一个真实 JD（脱敏）；
2. 先给判断：能投/谨慎/别投；
3. Agent 拆 3 个信号：职责模糊、年限/薪资不匹配、隐性加班/外包；
4. 一句“怎么改简历/怎么问 HR”；
5. 评论区留 JD，下期拆。

这条借 D1 的“避坑形式”和 C3 的“亲测 + 狠洞察”，但用你自己的程序员身份，不冒充 HR。
