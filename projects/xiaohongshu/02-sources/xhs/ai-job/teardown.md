## 一、先看结论

小红书“AI 找工作”内容已经分成 4 类：

| 类型 | 代表 | 数据特征 | 风险 |
|---|---|---|---|
| 自动投递 | Codex/Agent 自动投简历 | 流量最高，1.1 万赞起 | 平台规则、账号安全、隐私、诚信 |
| 简历提示词 | 4 步改简历 | 收藏极高，1.5 万藏 | 同质化，容易被复制 |
| 全流程 | Claude 手搓找工 | 收藏 > 点赞，信任强 | 制作成本高，需要真实过程 |
| JD 避坑 | 这个 JD 能投吗 | 评论精准，收藏高 | 需要真实案例和判断框架 |

**我们的位置：**

> **不自动投，先判断。**
>
> Agent 负责收集、核实、匹配；人负责最后确认和投递。

这不是“道德姿态”，是差异化：自动投递已经很卷，而且评论区全是成本、格式、安全、合法性质疑。

## 二、小红书 5 条样本

### X1：codex 自动化投简历这么爽

- 作者：奔跑的大海
- 数据：1.1 万赞 / 1.6 万藏 / 126 评
- 类型：视频，录屏为主
- 封面：聊天框里写“请详读我的简历……帮我完成投递”，字幕“这个岗位是发布了多久的”

**开头：**

> “以前我顶多把简历扔给 GPT 改完，我自己去投。现在 Codex 可以帮我找岗位、改简历、投递。”

**结构：**

- 一句话给结果；
- 录屏展示 Codex 操作；
- 没有长篇教程，靠“结果”吸引。

**评论区在问什么：**

- “一个月 token 消耗堪比雇了个人”（208 赞）；
- “没那么便宜”；
- “能投国内软件吗，会有合法性问题吗”；
- “Workday 一格格填信息，Codex 也能解决吗”；
- “AI 生成简历 AI 感太重，正常投 100 份 5 个面试，这么投 100 个能有 3 个就偷着乐”；
- “格式会乱”“个人信息喂给 AI 有安全风险”。

**结论：**

- 流量最大；
- 但评论区不是“求教程”，是“质疑成本和效果”；
- **不适合作为我们的主推荐**，但适合作为“反面对比”素材。

### X2：别对 AI 说帮我优化下简历，4 步指令照抄

- 作者：景维 AI 笔记
- 数据：6620 赞 / 1.5 万藏 / 155 评
- 类型：图文/视频，提示词卡片
- 封面：深绿色背景，大字“提炼岗位关键词”，小字“提示词 1/5”“你是一名资深招聘官”

**开头：**

> “不要对 AI 说帮我做份简历、帮我优化下简历。这就像让清华博士生帮你当实习生，太浪费。”

**结构：**

1. 找 5～10 个目标岗位；
2. 让 AI 提炼 5 个核心能力关键词；
3. 用关键词改写经历；
4. 对照简历找差距；
5. 量化成果、换行动词；
6. 追加模拟面试提示词。

**评论区在问什么：**

- 大量用户直接复制提示词；
- “先提炼关键词，再改经历，这个顺序比直接润色靠谱”；
- “简历写得好，面试一问三不知也没用”；
- 作者补了模拟面试提示词。

**结论：**

- **收藏极高**，因为“可照抄”；
- 适合做“简历/面试”系列；
- 但同质化严重，必须加真实 before/after 才有差异。

### X3：🇩🇪找工作：Claude 手搓找工全流程（上）

- 作者：柏林 Baguette
- 数据：1424 赞 / 2005 藏 / 47 评
- 类型：图文/长文 + dashboard 截图
- 封面：申请进度 dashboard（20 个申请、3 进行中、7 等待、10 结束）

**开头：**

> “试水一下现在的就业市场，也想看如何用 AI 高效找工作，结果确实把我惊艳到了。”

**结构：**

1. 用 Claude Code 从零手搓；
2. 先聊清楚：喜欢/不喜欢的工作、地点、职级、远程比例；
3. 生成筛选标准 Markdown；
4. 初次检索，人工反馈，持续更新标准；
5. 按“内容匹配度 + 公司/行业前景”两个维度打分；
6. 求职信、薪资调研；
7. **人工去官网投**。

**评论区在问什么：**

- “很多求职网站禁止 AI 爬数据”；
- 作者回复：德国基本能爬，LinkedIn 有次数限制；
- 有用户补充自己的 4 个对话工作流：
  - A 扫目标公司官网；
  - B 按关键词找名单外公司；
  - C 判断匹配、写简历/求职信；
  - D 当监工检查；
  - **投递这一步手动，GPT/Claude/Muse 都会出错**；
- “额度不够”“上下文占用太多”。

**结论：**

- 这是最接近“精投”的模型；
- **收藏 > 点赞**，用户想照着做；
- 关键不是“自动投”，是“先定标准，再筛，再人工投”。

### X4：招聘邪修：AI 帮我找工作，亲测有效

- 作者：胜子｜17 年国企 HR
- 数据：1199 赞 / 1739 藏 / 60 评
- 类型：图文，纯文字大字封面
- 封面：米白底，黑字“找工作 别自己刷 招聘软件了”，顶部“17 年国企 HR·亲测”

**结构：**

1. 简历脱敏；
2. 让 AI 匹配岗位；
3. 核实岗位是否真在招；
4. 分梯队、改简历、准备降薪谈判、输出报告；
5. 人工确认投递。

**核心洞察：**

> “很多岗位挂在那儿，其实早就不招了。不是你不行，是那个坑根本不存在。”

**评论区：**

- “先 AI 筛选，最后手动投吗？”作者确认；
- “我两个月前就这样做，没用”；
- “AI 推荐的工作网址已经荒废十多年”；
- “别删，等我找工作用”。

**结论：**

- 身份 + 亲测 + 3 步 + 一个狠洞察；
- 这是“AI 帮找工作”最值得参考的写法；
- 但不要冒充 HR。

### X5：这个 JD 能投吗？从岗位介绍就能看出是不是坑

- 作者：长缨不嘤嘤
- 数据：5184 赞 / 4152 藏 / 19 评
- 类型：视频 + 手写白板
- 封面：手写 JD 拆解 + 红色大字“小红书首届 JD 锐评大赛”

**结构：**

- 开头疑问句；
- 视频拆 JD；
- 置顶评论征集 JD；
- 评论区变成“奇葩 JD 共赏”。

**评论区：**

- “五险一金不是福利，是法律规定的”；
- “很多公司没有公积金，试用期社保也没有”；
- “JD 鉴坑技能很实用，AI 岗写得越花哨越要警惕”；
- “真正靠谱的团队 JD 反而写得克制具体”。

**结论：**

- 疑问句 + 避坑 + 评论区征集；
- 评论少但精准；
- 最适合做“JD 避坑”系列。

## 三、生财 3 条样本

### S1：千寻《AI 爬虫实操：不懂代码，半小时教你从 Boss 直聘爬取数据》

- 数据：119 赞 / 49 藏 / 6441 阅读
- 类型：7000 字技术教程
- 核心：5 步
  1. 确定目标网站和数据；
  2. 打开浏览器 Network；
  3. 找到 joblist 请求；
  4. 复制请求信息给 AI；
  5. 运行 AI 代码，导出 CSV。

**可学：**

- “把网页数据变成 Excel”这个结果很直观；
- 先讲朋友痛点，再讲步骤；
- 有真实文件截图。

**不能照搬：**

- 平台规则、反爬、账号风险；
- 不适合作为“自动投递”教程；
- 我们只做小批量、公开页面、人工确认。

### S2：唐承佳《一文讲懂：我们是如何把 BOSS 直聘招聘流程自动化的》

- 数据：149 赞 / 14 藏
- 类型：招聘方视角
- 核心判断：

> 招聘流程 80% 是重复工作，20% 需要判断和情感交流。

**可学：**

- 用“80/20”解释为什么要自动化；
- 先列痛点，再讲方案；
- 自动打招呼被求职者认为“像机器人”，说明自动化有边界。

**注意：**

- 这是 HR 侧，不是求职者侧；
- 不能直接套用“批量打招呼”到求职。

### S3：超级标 17《付费 MCP》

- 数据：699 赞 / 177 藏 / 1.37 万阅读
- 关键边界：

> 招聘数据 MCP 可以返回岗位条件；**替人投递或承诺录取不属于本项目。**

**可学：**

- 数据可以做成产品；
- 但“投递/录取”是边界，不能碰；

## 四、拆完后，别人到底怎么写

### 1. 开头只有三种

| 类型 | 句式 | 例子 |
|---|---|---|
| 结果型 | 我让 AI 帮我做了 X | codex 自动化投简历这么爽 |
| 反常识型 | 别对 AI 说 X | 别对 AI 说帮我优化简历 |
| 疑问型 | 这个 X 能 Y 吗 | 这个 JD 能投吗 |

### 2. 中间只有四种结构

| 结构 | 适合 | 例子 |
|---|---|---|
| 一句话 + 录屏 | 自动投递/工具 | X1 |
| 4 步 + 提示词 | 简历/面试 | X2 |
| 全流程 + dashboard | 精投/系统 | X3 |
| 3 步 + 一个洞察 | 方法/避坑 | X4、X5 |

### 3. 封面只有五种

- 聊天框/录屏；
- 提示词卡片 1/5；
- dashboard；
- 纯文字大字报；
- 手写白板。

**没有一种是精修海报。**

### 4. 评论区才是正文

- 自动投递：成本、格式、安全、合法性、Workday；
- 简历：求提示词、求模板、面试怎么办；
- 全流程：爬虫限制、额度、上下文；
- JD：五险一金、公积金、奇葩 JD。

**下一条内容，不应该从灵感来，应该从评论区来。**

## 五、我们分几个系列

不要把所有“AI 找工作”塞成一个系列。建议 4 个：

### S1《AI 找工作实验》

- 一条一批数据；
- 20 个 JD，跑完输出 3 个发现；
- 例：多少岗位过期、多少匹配、多少人卡在简历；
- 作用：建立“真的跑过”的信任。

### S2《JD 避坑》

- 一期一个 JD；
- 3 个隐藏信号；
- 结尾征集下一个 JD；
- 作用：搜索、收藏、评论。

### S3《AI 简历/面试》

- 4 步改简历；
- 模拟面试；
- before/after；
- 作用：高收藏、高私信。

### S4《Agent 实测/搭建》

- 怎么收集、清洗、核实、匹配；
- 不教自动投；
- 作用：技术信任、商单、产品化。

**先做 S2 + S1，再做 S3，最后 S4。**

原因：

- S2 有 D1 的 5184 赞验证；
- S1 有 C3/X3 的“真实跑过”信任；
- S3 收藏高但同质化；
- S4 门槛高，先别做。

## 六、完整数据怎么跑

“完整”不是爬全站，而是**跑完一个完整小批次**。

### 范围

- 1 个岗位方向（如 Java 后端 / AI 应用）；
- 1 个城市；
- 20 个 JD；
- 10 个官网 + 10 个 Boss（或公开渠道）。

### 五步

```text
收集 → 清洗 → 核实 → 匹配 → 输出
```

#### 1. 收集

- 官网招聘页优先；
- Boss 只读、低频、登录自己的账号；
- 不绕过验证码、不批量高频、不自动投递。

#### 2. 清洗

统一字段：

`公司 / 岗位 / 来源 / 地点 / 薪资 / 年限 / 职责 / 硬技能 / 软技能 / 发布时间 / 是否在招`

#### 3. 核实

- 岗位是否还在；
- 发布时间；
- 招聘者活跃度；
- 是否长期重发。

#### 4. 匹配

- 必须满足：年限、地点、核心技术；
- 加分项：行业、项目、工具；
- 差距：缺 2～3 个能力；
- 简历建议：改 2 条。

#### 5. 输出

三张表：

1. 重点投；
2. 保底投；
3. 别投。

加三个发现：

- 过期率；
- 匹配率；
- 最缺的能力。

## 七、帖子怎么写给大众看

### 结构

1. **开头**：一个具体结果/反常识/疑问；
2. **痛点**：为什么手刷没用；
3. **方法**：3～5 步，不出现代码；
4. **真实数据**：N 个 JD、X 个过期、Y 个匹配；
5. **一个例子**：一个 JD 的 3 个信号；
6. **边界**：不自动投、人工确认；
7. **CTA**：评论区留 JD。

### 生财体

> 身份 + 真实数据 + 3 步 + 一个狠洞察 + 边界 + CTA

### 标题方向

- `别再一个个刷招聘软件了：我先让 Agent 筛了一遍`
- `这个 JD 能投吗？我让 Agent 拆了 3 个隐藏信号`
- `我让 Agent 读了 20 个 JD，发现很多岗位根本不招`
- `AI 帮我找工作，但我最后一步还是自己投`

### 配图

1. 封面：一个问题/一个结果；
2. JD 列表；
3. 3 个信号表；
4. 重点/保底/别投；
5. 简历修改；
6. 边界 + CTA。

### 不要

- 不要写“自动投递”；
- 不要写“100% 匹配”；
- 不要编“帮 100 个人找到工作”；
- 不要放完整 JD 原文；
- 不要制造焦虑。
